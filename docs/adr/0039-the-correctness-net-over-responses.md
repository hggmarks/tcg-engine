# The correctness net over responses

Self-play and a Golden Game now exercise Response Windows, the Stack and activated abilities on the shipped Response decks, under every Invariant of ADR-0020, ADR-0026 and ADR-0031 (ticket [36], #87, of the Responses roadmap #83). It is ADR-0035's net applied to the Response Ruleset. No new Invariant: the twelve existing ones cover Passes, pushes, Fizzles and Activates. The Uniform Random Policy, the Step Cap, `FailureKind`, the harness API and `MAX_STEPS` are unchanged, and nothing in `src/`, in the harness or under `rulesets/` changes (the PR touches no file under `rulesets/`). Coverage is counted in the tests from the Game Record and the Event Traces, as ADR-0026's `effect_use` and ADR-0035's `choice_use` are.

**Decks: kept.** Measured first, with the Response decks of ADR-0037 and ADR-0038 as they are: every count below is at least 1 over the 1,000 pinned Seeds (the lowest, `responses_to_responses`, is 305), so no card is swapped, the decks stay 50 creatures, no Card Instance Id moves and `response-ruleset.md` and `.yaml` do not change. The deck test the 100-Seed test used to hold, that both decks list `swift_sparrow`, `flash_fox` and `skittish_hare`, is now `the_response_sample_decks_hold_the_fast_cards_and_the_ability_card`.

**Coverage, counted over the 1,000 pinned Seeds in the same pass** as the Invariants (`response_self_play_ends_every_game_over_1000_seeds_with_every_invariant_holding`; no second 1,000-Seed loop). `ResponseUse` has five counts. The Stack depth is carried through the creation trace and every Event Trace of the Game in order (`ItemPushed` adds one, `ItemResolved` and `ItemFizzled` take one, with checked arithmetic), and must be 0 at the end exactly when the final GameState's Stack is empty. Five separate asserts, each naming its count when it fails (`coverage count responses_to_responses is 0 over Seeds 0..1000`). Measured:

| Count | Defined as | Over Seeds 0..1000 |
|---|---|---|
| `responses_pushed` | an `ItemPushed` while the depth before the push is at least 1 | 1,684 |
| `responses_to_responses` | an `ItemPushed` while the depth before the push is at least 2 (depth 3 after it) | 305 |
| `fizzles` | each `ItemFizzled` | 143 |
| `abilities_used` | each `Action::Activate` in the records; also equal, Game by Game, to the number of `ItemPushed` whose source is `StackSource::Ability`, a mismatch being a failure line | 952 |
| `unanswered_windows` | see below | 18,835 |

**An Unanswered Window**, `unanswered_windows`, is a `Pass` whose trace resolves or fizzles an item whose source is the `attack` action and that the Action just before the Pass pushed: the attack window closed with the opponent passing and no response pushed. It is counted **from the traces only, by design**, because the harness exposes no listings. It proves that a window closed with no response. It does **not** prove that a response was available to the opponent: a Player with Priority and no untapped mana, no fast card and no ability in play also passes, and counts. The count says that the Pass-closes-the-window path is exercised, not that the policy chose it over a response.

**The Response Self-Play Pin.** `crates/tcg-selfplay/tests/selfplay/golden/response-self-play-seeds-0-1000.digest`, the third pin, is in the format of ADR-0021's and ADR-0026's (`digest_line`), compared in the same pass as the Invariants and rewritten only by the ignored `regenerate_response_self_play_digests`, whose mismatch message names that command. The same pass calls `verify_record` on the records of Seeds 0..100 (Invariants checked at every replayed step): that is what keeps the coverage of the 100-Seed test `the_response_ruleset_loads_and_self_plays_with_checks_on`, which is **retired** because the 1,000-Seed pass plays the same Seeds under the same checks and counts more; its deck assertion moved to the test above and its counts are superseded by the five. `self_play_with_checks_on_stays_green_on_all_three_rulesets` and `the_response_ruleset_self_plays_the_same_game_from_the_same_seed` are unchanged. The pass also asserts, for every Game, a Terminal Outcome, an empty Stack at the end and `TriggerCapRejections::Counted(0)`.

**The Response Golden Game.** `response-fizzle`, Seed 294, the shipped Response decks, 36 Actions, ending in a Leader kill by seat 0 (winners `[PlayerId(0)]`; `response_fizzle_script`, its cards named by `FIZZLE_*` constants). Seat 1 attacks with `skittish_hare` (tapping it) and passes the turn; seat 0 attacks the tapped hare (Action 23); seat 1 activates the hare (Stack depth 2); seat 0 answers with `fast_play` of `flash_fox` (depth 3, Action 25); three Passes follow: the fox resolves, the hare returns to its owner's hand, and the attack Fizzles because its target left (Action 28). Seat 0 then kills the Leader, seat 1 passing every window. The Seed was found by a throwaway search (a scripted bot over Seeds 0..1000, in four variants of its choices, keeping the shortest Game that holds a Fizzled attack, a Stack of depth 3 and a Terminal Outcome; Seed 294 gave 36 Actions); the search is not committed, the literal script is the Game. **The script is kept exactly as the search found it, including plays the Game does not need** (seat 0's `pyre_imp`, seat 1's `swift_sparrow` and `river_otter`): nobody should tidy it, because a shorter script would be a different Game and would need a new Seed search and new snapshots. Its snapshots are `crates/tcg-loader/tests/golden/response-fizzle.trace` and `response-fizzle.observed-by-player-0.trace` and `-1.trace`, in ADR-0017's and ADR-0031's layouts; a Pass is written `== action N: player P pass` and an Activate `== action N: player P activate card C ability A` in the Event Trace snapshot, and the observed ones use the Taken Action's own `Debug`. They are compared byte for byte, reporting the first differing line; the two observed snapshots differ from each other. `the_response_fizzle_golden_game_holds_a_fizzle_and_a_response_to_a_response` asserts outside the snapshot an `ItemFizzled` whose item is the `attack` and binds the hare as `target`, a Stack that is exactly 3 deep at its deepest (from the Events, and `stack().len() == 3` after the exact Action), the `Activate`, the `fast_play` push and the ability push, and a Terminal Outcome with winners `[PlayerId(0)]`. One ignored regenerator, `regenerate_response_golden_snapshots`, writes the three files and no other. The helpers (`GoldenGame`, `Played`, `play_game`, the snapshot writers, the comparison and the replay check) moved from `effects_ruleset.rs` to `crates/tcg-loader/tests/common/golden.rs` and are shared; no Effects or Small snapshot changes by a byte, which the existing snapshot tests and the freeze digests prove.

**Replay.** `replaying_the_record_of_response_fizzle_reproduces_its_game` builds a `GameRecord` from the script and asserts `replay` returns the same creation, the same Event Traces and the same final GameState as the Game played, as ADR-0035's replay tests do. There is no 1,000-Seed replay test for the Response Ruleset (no second loop); `verify_record` on Seeds 0..100 replays those.

**Step Cap.** The longest Game of the 1,000 is 194 Actions, so `longest * 2 < MAX_STEPS` keeps its headroom and `MAX_STEPS` stays 1,000.

**Throughput, measured.** Release, `cargo run --release -p tcg-selfplay --example self_play`, 1,000 Games per cell, Games per second (Actions per second), ADR-0035's layout and a Response row:

| Ruleset | Off | EngineOnly | On |
|---|---|---|---|
| Small | 196 (7,696) | 168 (6,586) | 20 (770) |
| Effects | 116 (5,779) | 99 (4,936) | 12 (623) |
| Response | 103 (7,814) | 83 (6,324) | 8 (631) |

Not optimised. The Small and Effects cells are the same code on the same Games as ADR-0035's table (190, 150, 18 and 110, 97, 12): the difference is the machine and noise. The Response Games are longer (75,929 Actions over 1,000 Games, against 49,880 for Effects: every attack opens a window and costs a Pass, and a response costs more), so Games per second fall while Actions per second with checks off are the highest of the three (7,814); with every check on, a Game costs about 120 ms per Game-second of checks, the observation checks scaling with the number of Actions as ADR-0031 found.

**The test profile.** Measured the same way on both, warm (everything compiled, then `cargo test --workspace` timed): TEST_TIME

**Conflicts, amended in place.** ADR-0017 (the regenerators; a committed Golden Game now holds Passes and Activates), ADR-0020 and ADR-0026 (what self-play runs; the pins are three), ADR-0031 (observed Golden Games; the throughput table), ADR-0035 (the Golden Game helpers moved; the throughput table), ADR-0037 and ADR-0038 (their out-of-scope lists deferred coverage counts, the Response Golden Game and the pin to [36]). Each carries an `Amended by ADR-0039:` line and the clause is marked where it stands. No other ADR changes.

**Out of scope, by design.** New Invariants, other policies, optimisation (the cost of the `selfplay` binary included), new cards, any change under `rulesets/`, a change to the harness API, a listing-based count of unanswered windows, and a 1,000-Seed replay test.

**Status**: accepted
