# Response Windows and the Stack

A ruleset can declare **Response Windows**. An Action that opens one pays its cost at once and puts its effects on the **Stack**; the Players then respond or pass, and a pass resolves the top item (ticket [34], #85; checkpoint #78 decisions). Activated abilities come in [35], on top of this; the Response Ruleset is the ruleset that uses it.

**`windows`.** A top-level list `windows: [{ id, opened_by: [action ids], actions: [action ids] }]` (`RulesetDefinition::windows()`, `Window { id, opened_by, actions }`, `WindowId`; `WindowDraft`). An Action named in `opened_by` and taken outside a window is **pushed** as the first item and opens the window. Every Action taken while a window is open is pushed. The Actions a Player may take while it is open are its `actions`; they are declared Actions and need not be listed by a phase. `RulesetDefinition::window_opened_by(action)` gives the window an action opens.

**The split at declaration.** A pushed Action's params are bound and its cost is paid at once, in its own transition, with the cost Events as before; its effects do not run but become a **Stack Item**, announced by `ItemPushed { item }`. The trace of a push is: the cost Events, `ItemPushed`, the Trigger Resolution (as after any Action), `DecisionPending` if that paused, then the win conditions.

**The Stack.** `GameState::stack()`, a list of Stack Items bottom first, in the GameState. `StackItem { controller, source, bound }` (public fields): the Player who took the Action, its `StackSource` and the cards it bound, in param order. `StackSource` is an enum with one variant, `Action(ActionId)`; [35] adds `Ability { .. }` beside it, and it is deliberately not `#[non_exhaustive]`, so every `match` on it shows [35] the places to handle. `BoundCard { param, card, zone, left }`: the param, the card, the zone it was in **once the cost was paid** (the zone it was bound from, unless the cost moved it: `fast_play`'s cost moves its card from the hand to `holding`, so it is bound in `holding`, and without this rule it would always Fizzle) and `left`.

**The window and Priority are derived, never stored.** A window is open exactly while the Stack is not empty: the open window is the one whose `opened_by` holds the source Action of the bottom item (`open_window`). **Priority** is the first Player in seat order other than the controller of the top item, the rule of `decider: opponent`; `GameState::priority()`, `None` when the Stack is empty. Windows need exactly 2 Players (`WindowsNeedTwoPlayers { players }`, like `OpponentDeciderNeedsTwoPlayers`).

**One pass resolves.** The Player with Priority either takes a window Action (pushed; Priority flips) or passes. **`Action::Pass { player }`** is the third engine variant beside `Declared` and `Answer`. A pass resolves the top item: its trace is `ItemResolved { item }` first, the item's effect Events, the Trigger Resolution, the pause if any, then the win conditions. The resolving item is popped by `ItemResolved` before its effects run, so its own effects never mark it; lower items that bind the same card do get marked. The next item down then follows the same rule, and the window closes when the Stack is empty and play returns to the Active Player in the Action phase.

**Listing and the Deciding Player.** While a window is open the Legal Actions of the Player with Priority are `Pass` followed by the window's `actions`, in the order the window lists them, each action's candidates as in ADR-0018, all through `transition`; everyone else has none. The **Deciding Player** is the Decider while a decision is pending, else the Player with Priority while a window is open, else the Active Player. A trigger woken by a push's cost or by a resolving item resolves in that transition, as before, and may pause on a Choice: the decider decides until the Answer, then the Player with Priority.

**Rejections.** New: `PassWithoutWindow`, `PassWhileDecisionPending`, `ActionNotInWindow { action }` and `CardAlreadyTapped { card }`. The checks run in this order: `GameOver`, `UnknownPlayer`, `NotDecidingPlayer`; then per variant: a Declared Action, `DeclaredWhileDecisionPending`, `UnknownAction`, then `ActionNotInWindow` if a window is open (the window does not list it) or else `ActionNotInCurrentPhase`, then the binding of ADR-0015; a Pass, `PassWhileDecisionPending`, then `PassWithoutWindow`. A Pass from a Player without Priority is `NotDecidingPlayer`, checked first.

**Events**, each folded by `GameState::apply`. `ItemPushed { item }` puts the item on top (the controller is a Player, each bound card is in its zone, none has `left`); `ItemResolved { item }` and `ItemFizzled { item }` pop the top item, which must equal `item` (`StackEmpty`, `NotTopItem`), and `item.fizzles()` must be false for the first and true for the second (`FizzleMismatch`, which also refuses an `ItemPushed` of an item that already has a card that left); `CardMoved` sets `left` on every bound card of every item that binds the moved card; `TurnBegan` and `PhaseBegan` with a non-empty Stack are `StackNotEmpty`; `GameEnded` clears the Stack, as it clears the Pending Decision. Effect Events wake triggers exactly as before: triggers stay off the Stack.

**Fizzle**, all or nothing. A Bound Card is **gone** once it has moved, even if it came back: `left` is state, not history, so it needs no log of past Events. An item Fizzles when any card it bound has `left`; nothing else is compared and `where` conditions are not read again. A Fizzling item does nothing, its cost is not refunded, and `ItemFizzled { item }` takes the place of `ItemResolved`.

**New cost forms**, needed by "an attack moves its tap into the cost" and "a fast play's cost moves the card": `Cost::TapCard { card }`, `tap: { card: { ref: <param> } }` (an already tapped card is `CardAlreadyTapped`; every card type the param may take must declare a bool `tapped`, else `TapCardWithoutTappedState { card_type }` at `cost[i].tap.card`), and `Cost::Move { card, to }`, `move: { card: { ref: <param> }, to: <zone> }` (the checks of the `move` effect). `tap` has two shapes in the file, `{ zone, count }` and `{ card }`, read through one raw type, so a missing key is reported as before. [35] adds `ref: self` to the first.

**Load checks**, typed errors at the Definition Path, checked after the actions and before the turn, in this order: windows need 2 Players, at `windows`; per window its id (`InvalidId`, `DuplicateId`), each `opened_by` entry (`DanglingReference { target: Action }`, or `DuplicateWindowOpener { action, first }` for an action in two windows, or twice in one) and each `actions` entry (`DanglingReference`, `DuplicateId`), addressed `windows[<id>].opened_by[i]`; then, per pushed action (one a window lists or opens) in declaration order: a card param that is neither bound from a `public` zone nor moved to one by a `move` cost is `PushedCardNotPublic { param, zone }` at the param or at its `one_of[i]` alternative, and an `end_turn` in its effects is `EndTurnInPushedAction` at the effect. A Choice in a pushed action's effects is the existing `ChoiceOutsideTriggeredEffect`. ADR-0027's `UnlistedAction` accepts an action listed by a window's `actions`; `opened_by` alone lists nothing.

**Win timing is unchanged** (ADR-0014): the win conditions run at the end of every accepted transition, pushes and passes included; a Terminal Outcome clears the Stack and any Pending Decision.

**Observing.** The Stack is fully public. `ObservedGameState::stack()` shows `ObservedStackItem { controller, source, bound }`, each `ObservedBoundCard { param, zone, card: Option<ObservedCard> }`, `None` once the card has left; `priority()` and `deciding_player()` are derived as in the GameState. The three Events are observed in full (`ObservedEvent::{ItemPushed, ItemResolved, ItemFizzled} { item }`); the observed fold pushes and pops like `apply` (`EventDoesNotFit` on a mismatch) and sets a bound card to `None` on any observed move of it. `ObservedAction::Pass` and `TakenAction::Pass` carry the Player; Observed Legal Actions and `translate_action` cover them. The self-play Relabelling maps the cards of Stack Items and of the three Events, and the `state_difference` of the Recomputed GameState has a Stack branch.

**The Response Ruleset** is the ruleset of Phase F (`rulesets/response-ruleset/`, id `response`), a copy of the Effects Ruleset with the `holding` zone, the creature field `fast`, `attack` tapping its attacker as a cost, `fast_play` and the `attack_response` window; see its `.md`. **The Effects Ruleset is frozen** from this ticket on, like the Small Ruleset since Phase C: rule decisions go to the Response Ruleset, and a digest test pins every Effects ruleset, catalog, deck and golden file and its self-play pin (`the_effects_ruleset_is_frozen_since_phase_f`).

**Out of scope**, for later tickets: activated abilities, coverage counts, the Response Golden Game and a Response self-play pin, triggers on the Stack, priority in every step, Choices in a pushed Action's effects, responding to one's own item while the opponent holds Priority, more than two Players, replacement effects, layering, durations.

**Conflicts, amended in place.** ADR-0012 (the Game waits only in the Action phase and only the Active Player acts), ADR-0015 (an action's cost and effects run together; the rejection order), ADR-0018 (who can act, how listing builds candidates, Listing Order), ADR-0019 (the Action variants a record holds), ADR-0020 (the rulesets self-play runs), ADR-0022 and ADR-0026 (only the Small Ruleset is frozen; the current phase's ruleset), ADR-0023 (triggers are scanned after an action's costs and effects), ADR-0027 (`UnlistedAction`), ADR-0028 to ADR-0031 (what is always visible, the Observed Event table, Observed Actions, the Relabelling) and ADR-0033 (`Action` has two variants; the Deciding Player) each carry an `Amended by ADR-0037` line and mark the affected clause where it stands. ADR-0014's win timing is unchanged.

**Status**: accepted
