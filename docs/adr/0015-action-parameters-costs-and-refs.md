# Action parameters, costs and refs

An action definition is `{ id, params, cost, effects }`; `params` and `cost` are optional lists. A param is `{ name, zone, card_type }`: a card instance of that type in that zone of the acting Player, who is also its owner (an `owner` key arrives with [11] inside `one_of`; `where` and `one_of` stay unknown keys). The declarative Action carries one Argument per param (`Argument::Card(CardInstanceId)`), bound to params **by position**. A Cost is `tap: { zone, count }`; the effects are `end_turn`, `move: { card, to }` and `set_state: { card, state, value }`. This amends ADR-0012: the Action shape, and the order of the Rejections: unknown Player, not the Active Player, unknown action, action not in the current phase, then the argument count, then for each param in order the unknown card, the owner, the zone and the card type, then the costs in order, then the effects. The whole transition runs on the clone of ADR-0002, so paying costs is atomic.

A `ref` is `<param>` (a Card Ref) or `<param>.<name>` (a Value Ref). The loader keeps it as text and only the engine parses it (`<id>` or `<id>.<id>`, else `InvalidReference`: unlike the `DanglingReference` that ADR-0009 and the Identifier entry promise for a reference that breaks the grammar, a malformed ref text gets its own error, because a ref has a syntax of its own). Validation resolves it once, in this order: the text, the param (`DanglingReference` to a param), the name against the param's card type as a field or an instance state (`DanglingReference` to a field or instance state; a name the type declares as both is `AmbiguousReference`), then the type against the slot: `tap.count` needs an int value and `move.card` and `set_state.card` need a card (`ReferenceTypeMismatch`). The result is a `CardValue::Field` or `CardValue::State`, so nothing looks a name up by string at run time. `tap.count` takes only a ref; literals arrive with the expressions of [11].

Validation order inside an action is its params, its cost, then its effects. A `set_state` checks its `state` against the card type of its param, not against every card type as an automatic step does (a param has one known type): a state that type lacks is a dangling instance state, and a value of another type is a `StateValueTypeMismatch`. A `tap` cost validates its zone, then its count, then (as `untap` does) that some card type declares `tapped` and that every card type that does declares it as a bool (another type is a `StateValueTypeMismatch`).

`tap` takes the first `count` cards, in the GameState's list order (bottom first), of the acting Player's `zone` whose card type declares `tapped` and whose value is false; this holds even in an unordered zone such as the Mana Zone, where mana cards are indistinguishable (revisit this when a ruleset has distinguishable resources). This qualifies ADR-0013: "no order to keep" there is about the Top and positions of an unordered zone; its list is still a deterministic order, and `tap` uses it. A count of 0 taps nothing, and a negative resolved count is the Rejection `NegativeCount`; too few untapped cards is `NotEnoughUntappedCards { zone, required, available }`. `move` emits `CardMoved` with `from` taken from the GameState (`GameState::zone_of`) and `player` the card's owner; `set_state` emits `CardStateChanged` only if the value changes. `CardDataMismatch` is an internal Rejection for a card whose definition or value is missing, and `UnboundParam { param }` one for a ref that names a param with no bound argument; neither is expected after validation.

The known gap of ADR-0012 is **still open**: validation does not check that the Action Phase can be left, nor that an action ends at most one Turn (`[end_turn, end_turn]`), nor that `end_turn` is the last effect: `[end_turn, move ...]` loads and the `move` runs in the next Player's Turn. Nothing here changes it. "Effect" now has two meanings, kept apart in `CONTEXT.md`: Action Effects, built from engine primitives and decided here, and Card Effects (abilities of a card), which are out of scope.

**Status**: accepted
