# Narrowing intersects and an overflowing alternative does not fit

Two gaps that the reviews of PR #55 and PR #57 left open, closed before the parameter and Ref code is reused for choices (roadmap #73, checkpoint #67).

**Narrowing intersects.** An `if` whose condition is exactly `is_card_type: [{ ref: p }, T]` narrows `p` in `then` to its own possible card types that are in `[T]`, in the param's order (`Refs::narrowed(param, types)` keeps the param's types that `types` lists). If that is empty, `T` is none that `p` can have and the definition does not load: `DefinitionErrorKind::ImpossibleCardType { param, card_type }`, at the path of the test (`actions[x].effects[i].if.is_card_type`, and in a Card Effect, wrapped in `InvalidCardEffect`, `cards[c].effects[i].do[j].if.is_card_type`). Before, `then` was checked against exactly `{T}`, so a param or `self` could be retyped as a card type it can never have and a Ref that is valid on no real card type was accepted. The `else` rule is unchanged: the param's types minus `T`, all of them if none would be left. It is already a subset of the param's types and never a retype, so it needs no new error. `is_card_type` anywhere else (inside `and`, a `where`, a `when`) still narrows nothing, and an impossible type there is simply false.

**An overflowing alternative does not fit.** When a param has two or more alternatives and the `where` of one raises `Rejection::DerivedValueOverflow` (a derived read, ADR-0024, that overflows) *(Amended by ADR-0043: or `Rejection::ArithmeticOverflow`, an `add` or `sub` that overflows)*, that alternative does not fit: binding tries the next one, and if none fits the Rejection is `NoAlternativeMatched { param, card }`, with the GameState unchanged and no Event. A param with one alternative keeps the overflow as its Rejection. Only a `DerivedValueOverflow` *(Amended by ADR-0043: or an `ArithmeticOverflow`)* raised while evaluating a Where Condition counts; every other error of the check (an inconsistency between the GameState, the catalog and the definition) still aborts the binding. Listing goes through the same `bind_param` (ADR-0021), so a card that fits only through a later alternative is listed, and one that fits none is not.

**Conflicts.** ADR-0016's narrowing "to `{T}` in `then`" becomes an intersection (marked there), and its "for several, the first alternative that fits wins and none fitting is `NoAlternativeMatched`" now counts an overflowing `where` as not fitting (marked there). ADR-0024's "an overflow is the typed `DerivedValueOverflow`" has this one exception (marked there). ADR-0022's `self` narrowing is the same code and gets the same error. No other ADR changes. The Small Ruleset is untouched (ADR-0022) and still loads, because its only `is_card_type` test, of `target` for `creature`, names a type `target` can have.

**Status**: accepted

Amended by ADR-0043: an `ArithmeticOverflow` in a `where` makes its alternative not fit, as a `DerivedValueOverflow` does (marked above).
