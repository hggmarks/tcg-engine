# Golden Games are Event Trace snapshots

A Golden Game is a Seed, the two sample decks and a literal list of Actions in the test source. Its Event Trace, from Game creation to the Terminal Outcome, is compared byte for byte with a committed text snapshot of one `Debug` line per Event, so any change to a rule, to the order of Events or to an Event's shape shows up as a failing test with the first differing line. The format is test-only: it is not a serialization format and changes when an Event's shape changes. Snapshots are rewritten only by the ignored test `regenerate_golden_snapshots` *(Amended by ADR-0031 and ADR-0035: a Golden Game's observed snapshots have their own ignored regenerator, `regenerate_observed_golden_snapshots`, and the pausing Golden Game's three snapshots have `regenerate_pausing_golden_snapshots`; each is ignored and run on purpose; amended by ADR-0039: the Response Golden Game's three snapshots have `regenerate_response_golden_snapshots`, which writes those three files and no other)*, never by a normal run, so a change to a snapshot is always a deliberate, reviewed diff. The comparison does not trim or normalize, `.gitattributes` fixes the line endings, and there is no snapshot dependency, no environment switch (`std::env::var` is disallowed) and no policy that searches for accepted Actions. No older ADR conflicts: ADR-0010 makes Events the only way a GameState changes, which is what makes the trace a complete record.

**Amended by ADR-0033:** `Action` and `TakenAction` became enums, and their derived `Debug` lines would have changed, which would have changed every committed snapshot and the frozen Small Ruleset pin. *The `Debug`-line convention is kept for what exists: a test-side renderer, one small documented helper each for the self-play digest and for the observed snapshots, writes a Declared Action as the `Debug` line of the struct it was, `Action { player: .., action: .., arguments: [..] }` and `TakenAction { .. }`; an Answer, which no committed Game holds, renders as its own `Debug`. *(Amended by ADR-0035: the Effects pausing Golden Game holds Answers. Its Event Trace snapshot writes an Answer as `== action N: player P answer option I` or `answer card C`, and its observed snapshots use the Taken Action's own `Debug` line.)* The engine types carry no custom `Debug`, and no `.digest` or snapshot changes.*

**Amended by ADR-0035:** the Effects Golden Game and its two observed snapshots were regenerated because the shipped Effects decks changed, and a second Effects Golden Game, the pausing one, joins them with its own snapshots and its own ignored regenerator, `regenerate_pausing_golden_snapshots`.

**Amended by ADR-0039:** a committed Golden Game now holds Passes and Activates: the Response Golden Game, `response-fizzle`. Its Event Trace snapshot writes a Pass as `== action N: player P pass` and an Activate as `== action N: player P activate card C ability A`; its observed snapshots use the Taken Action's own `Debug` line. The helpers that write and compare snapshots are shared by the Small, Effects and Response Golden Games *(Amended by ADR-0045: and the Duel Golden Game; the `pass` helper moved out of the shared file into the two tests that use it, since the Duel has no `pass_turn`)* in `crates/tcg-loader/tests/common/golden.rs`, and no Small or Effects snapshot changes by a byte.

**Amended by ADR-0045:** the Duel Ruleset has a Golden Game too, `duel-direct-kill`: an Event Trace snapshot and one observed snapshot per Player in the layouts above, rewritten together, and alone, by the ignored `regenerate_duel_golden_snapshots`. Its script holds only Declared Actions (the Duel has no Response Window and its Game has no Choice), so the renderer needed no new Action line; no Small, Effects or Response snapshot changes by a byte.

**Status**: accepted
