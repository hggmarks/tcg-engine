# The Turn cycle

Amended by ADR-0042: a Turn has one or more action phases; `end_turn` from an earlier one passes over the later ones, and `advance_phase` moves to the next (marked where each statement stands).
Amended by ADR-0037: while a Response Window is open the Player with Priority acts, not the Active Player, and the Game waits in the same Action phase for it.

A ruleset's `turn` is a list of phases, each addressed by id. A phase is either `automatic` (a list of steps that run in order when the phase begins) or has `actions` (a list of action ids the Active Player may take) *(Amended by ADR-0037: while a Response Window is open the Player with Priority may instead take that window's actions, or Pass)*. A turn has **exactly one phase with `actions`**: the Game waits there, and `end_turn` is the only way to leave it. *(Superseded by ADR-0042: a turn has one or more phases with `actions`, the Game waits in each it enters, and `end_turn` leaves any of them; `advance_phase` moves to the next one. The "relax it when a primitive that ends a phase arrives" below is this: `advance_phase` is that primitive, and an all-automatic Turn loop stays impossible because at least one action phase is required.)* *(Amended by ADR-0037: the Game still leaves it only through `end_turn`, and a window opened inside it must be empty first: `TurnBegan` and `PhaseBegan` with a non-empty Stack are `StackNotEmpty`)* This is what is well defined today, and it makes an all-automatic infinite Turn loop impossible; relax it when a primitive that ends a phase arrives.

`actions` is a minimal section, `{ id, effects }`, whose only effect is `end_turn: {}`. The declarative Action is `{ player, action: ActionId }`; ticket [10] adds typed arguments, params and costs. PassTurn is declarative: in the Small Ruleset `pass_turn` is listed in Main, and its `end_turn` effect resolves every phase after the current one (all automatic, as a turn has one phase with actions; Small's End is `automatic: []`; *Amended by ADR-0042: it enters the automatic phases after the current one and passes over any action phase among them without a `PhaseBegan`*), and then the next Player in seat order (`PlayerOrder::next_after`) begins Turn n+1 and their phases run until the action phase *(Amended by ADR-0042: the first action phase)*, all in the same transition. The Turn Number is the one of `crate::turn`; overflowing it is a `TurnNumberOverflow` rejection. Rejections are checked in this order: unknown Player, not the Active Player *(Amended by ADR-0037: not the Deciding Player: while a window is open that is the Player with Priority, and then the checks are `ActionNotInWindow` for a Declared Action and `PassWithoutWindow` for a Pass instead of the phase check)*, unknown action, action not in the current phase (no current phase, a phase the ruleset does not know, or one that does not list the action *(Amended by ADR-0027: the action phase lists every declared action, so this holds only when the current phase is absent, unknown to the ruleset or automatic; superseded by ADR-0042: with several action phases it also holds for an action that only another action phase lists; amended by ADR-0037: or when the action is listed only by a Response Window and none is open)*), then the effects. An accepted transition is atomic: it runs on a clone of the GameState.

`turn` is optional: absent means the Game has no Turns, creation stops after setup and every Action is rejected (as for `setup`, absent means no steps; *Amended by ADR-0027: no phase lists an action then, so such a ruleset declares none and every Action is `UnknownAction`*); `actions` absent means none. When `turn` is present the first Turn begins as the last part of Game creation, with the starting Player active.

The GameState gains the Turn Number and the current phase (both `None` in the Empty GameState), and four Events: `TurnBegan` (sets the Active Player and the Turn Number and clears the phase; it checks only that the Player exists, so a trace can start at any Turn Number *(Amended by ADR-0037: and that the Stack is empty, `StackNotEmpty`)*), `PhaseBegan` (requires a Turn in progress *(Amended by ADR-0037: and an empty Stack)*), `CardStateChanged` (the card exists, has the state, and the value has the type of the current value) and `DrawFromEmptyZone` (the zone exists and is empty; changes nothing). A Turn's trace is `TurnBegan`, then for each phase from the first `PhaseBegan` followed by its step events, stopping after `PhaseBegan` of the action phase; a PassTurn trace starts with `PhaseBegan` of the phase after Main. *(Amended by ADR-0042: stopping after `PhaseBegan` of the first action phase; an `advance_phase` trace is the `PhaseBegan` of each phase it enters, ending with the next action phase; an `end_turn` trace has no `PhaseBegan` for an action phase it passes over.)*

Step semantics: steps iterate the selected Players in seat order, the listed zones in order and the cards bottom first; `untap` (sets `tapped` to false) and `set_state` touch only cards that have the state *(Amended by ADR-0041: this is `set_state` with a `zone`; without one it sets a Player state of each selected Player, and `add_state: { player, state, amount }` is a new step that adds an int literal to one; both emit `PlayerStateChanged` only when the value changes)*, and an Event is emitted only for a card whose value actually changes. `draw` and `move` go one card at a time from the Top of `from` onto the Top of `to`. A turn `draw` whose source runs out emits ONE `DrawFromEmptyZone` per selected Player (not one per missing card) and stops that Player's draw (win conditions read it, ADR-0014); a `move` silently moves the cards there are, which is how the Small Ruleset's mana deck runs out. The setup draw still fails creation on an empty zone (ADR-0011, unchanged). Conditions are evaluated when the step runs; the only one is `first_turn`, true when the Turn Number is 1 *(ADR-0042 gives an Expression the same spelling and meaning; the Condition is unchanged)*, and an `if` step has `then` and an optional `else`. There is one Player Selector, `each` or `active`, accepted by setup and automatic steps alike *(Amended by ADR-0041: setup and automatic steps still take only these two; an action and a Card Effect take the selectors of their context for a Player-state read or write: `active`, `opponent`, `each` and, in a Card Effect, `controller`)*; `active` is the GameState's Active Player (the starting Player during setup).

The instance-state name `tapped` is reserved: the `untap` primitive (and #24's `tap`) gives it its meaning, and validation requires some card type to declare it as a bool when `untap` is used.

**Known gap, closed by ADR-0027** *(Amended by ADR-0027: validation now rejects all of this, and the text below says what was open until then)*. Validation did not check that the Action Phase can be left. It may list no action, or only actions without `end_turn`, and the Game then waits there forever. Nor does it check that an action ends at most one Turn: `[end_turn, end_turn]` ends two Turns in one transition, and the Player in between never gets a Main phase. An action that no phase lists loaded and was always rejected (`ActionNotInCurrentPhase`). None of this was checked because `end_turn` was the only effect.

Amends ADR-0010: the Opening Position now includes the start of the first Turn when the ruleset has a turn, and `Action` and `Rejection` are no longer empty enums. Amends ADR-0011: the `active` selector now exists.

Amended by ADR-0015: an Action also carries one Argument per Action Parameter, the rejections gain an argument count check and the card checks after the action is found to be listed in the current phase, and `actions` gains `params`, `cost` and the `move` and `set_state` effects. The known gap above is still open. *(Amended by ADR-0027: closed.)*

**Status**: accepted

Amended by ADR-0014: `Rejection::GameOver` is a new first check, before unknown Player, and win conditions are evaluated at the end of every transition, including these automatic steps. The `DrawFromEmptyZone` fact is what they read.

Amended by ADR-0016: the known gap is still open (no ticket yet) and now also includes an `end_turn` nested in an `if` effect, which the recursive effect runner executes like a top-level one. *(Amended by ADR-0027: closed, including the `end_turn` in an `if`.)*

Amended by ADR-0027: the known gap is closed; how a Turn is left is checked when the ruleset definition is validated.

Amended by ADR-0041: an automatic step may be a Player-state `set_state` (no `zone`) or `add_state`, and the Player Selectors depend on the context (marked above).
