# The Turn cycle

A ruleset's `turn` is a list of phases, each addressed by id. A phase is either `automatic` (a list of steps that run in order when the phase begins) or has `actions` (a list of action ids the Active Player may take). A turn has **exactly one phase with `actions`**: the Game waits there, and `end_turn` is the only way to leave it. This is what is well defined today, and it makes an all-automatic infinite Turn loop impossible; relax it when a primitive that ends a phase arrives.

`actions` is a minimal section, `{ id, effects }`, whose only effect is `end_turn: {}`. The declarative Action is `{ player, action: ActionId }`; ticket [10] adds typed arguments, params and costs. PassTurn is declarative: in the Small Ruleset `pass_turn` is listed in Main, and its `end_turn` effect resolves every phase after the current one (all automatic, as a turn has one phase with actions; Small's End is `automatic: []`), and then the next Player in seat order (`PlayerOrder::next_after`) begins Turn n+1 and their phases run until the action phase, all in the same transition. The Turn Number is the one of `crate::turn`; overflowing it is a `TurnNumberOverflow` rejection. Rejections are checked in this order: unknown Player, not the Active Player, unknown action, action not in the current phase (no current phase, a phase the ruleset does not know, or one that does not list the action), then the effects. An accepted transition is atomic: it runs on a clone of the GameState.

`turn` is optional: absent means the Game has no Turns, creation stops after setup and every Action is rejected (as for `setup`, absent means no steps); `actions` absent means none. When `turn` is present the first Turn begins as the last part of Game creation, with the starting Player active.

The GameState gains the Turn Number and the current phase (both `None` in the Empty GameState), and four Events: `TurnBegan` (sets the Active Player and the Turn Number and clears the phase; it checks only that the Player exists, so a trace can start at any Turn Number), `PhaseBegan` (requires a Turn in progress), `CardStateChanged` (the card exists, has the state, and the value has the type of the current value) and `DrawFromEmptyZone` (the zone exists and is empty; changes nothing). A Turn's trace is `TurnBegan`, then for each phase from the first `PhaseBegan` followed by its step events, stopping after `PhaseBegan` of the action phase; a PassTurn trace starts with `PhaseBegan` of the phase after Main.

Step semantics: steps iterate the selected Players in seat order, the listed zones in order and the cards bottom first; `untap` (sets `tapped` to false) and `set_state` touch only cards that have the state, and an Event is emitted only for a card whose value actually changes. `draw` and `move` go one card at a time from the Top of `from` onto the Top of `to`. A turn `draw` whose source runs out emits ONE `DrawFromEmptyZone` per selected Player (not one per missing card) and stops that Player's draw (win conditions read it, ADR-0014); a `move` silently moves the cards there are, which is how the Small Ruleset's mana deck runs out. The setup draw still fails creation on an empty zone (ADR-0011, unchanged). Conditions are evaluated when the step runs; the only one is `first_turn`, true when the Turn Number is 1, and an `if` step has `then` and an optional `else`. There is one Player Selector, `each` or `active`, accepted by setup and automatic steps alike; `active` is the GameState's Active Player (the starting Player during setup).

The instance-state name `tapped` is reserved: the `untap` primitive (and #24's `tap`) gives it its meaning, and validation requires some card type to declare it as a bool when `untap` is used.

**Known gap, to be decided when #24 and #25 extend effects.** Validation does not yet check that the Action Phase can be left. It may list no action, or only actions without `end_turn`, and the Game then waits there forever. Nor does it check that an action ends at most one Turn: `[end_turn, end_turn]` ends two Turns in one transition, and the Player in between never gets a Main phase. An action that no phase lists loads and is always rejected (`ActionNotInCurrentPhase`). None of this is checked today because `end_turn` is the only effect.

Amends ADR-0010: the Opening Position now includes the start of the first Turn when the ruleset has a turn, and `Action` and `Rejection` are no longer empty enums. Amends ADR-0011: the `active` selector now exists.

**Status**: accepted

Amended by ADR-0014: `Rejection::GameOver` is a new first check, before unknown Player, and win conditions are evaluated at the end of every transition, including these automatic steps. The `DrawFromEmptyZone` fact is what they read.
