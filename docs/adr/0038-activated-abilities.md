# Activated abilities

A card can carry an **activated ability**, a third Card Effect shape that its controller uses as a response. It goes on the Stack like a window Action and resolves through ADR-0037's machinery (ticket [35], #86; checkpoint #78 decisions).

**The shape.** `activated: { cost, do }`, an element of a card's `effects` beside the triggered and continuous ones (`CardEffect::Activated(ActivatedCardEffect)`, `costs()` and `body()`; `CardEffectDraft::activated: Option<ActivatedDraft { cost, body }>`). `cost` is optional and defaults to no steps; it takes the action cost steps (`tap: { zone, count }`, `tap: { card }`, `move: { card, to }`), checked with only `self` in scope (`ref: self` and `ref: self.<name>` work; any other name is `DanglingReference` to a param, wrapped as `InvalidCardEffect`). `do` has at least one effect (`MissingDo`, `EmptyDo`, at `activated.do`) and is checked with `self` in scope like a triggered `do`; `end_turn` in it, nested included, is `EndTurnInCardEffect`. **A Choice in `cost` or `do` is a load error**: `InvalidCardEffect { ChoiceOutsideTriggeredEffect }` at `cards[<id>].effects[<i>].activated.do[<j>].choose_one` (or `.choose_card`, or under `.then[k]` when nested), because the `do` has `self` but a Choice stays inside triggered `do`s: ADR-0033 and ADR-0034 found a Choice by the absence of `self`, which no longer says it, so the checker has its own flag. An unknown cost step is the loader's unknown-key error at `activated.cost[<i>]`. `activated` beside `on`, `if`, `do`, `while`, `modify` or `scope` is `MixedCardEffectShapes`; an element with none of `on`, `while` and `activated` is `MissingCardEffectShape`. The **Ability Index** of an activated effect is its position among all the effects of the card, counting every shape; it is a plain `u32` (the convention of `OptionOutOfRange { index }`). An activated effect is inert for triggers and for modifiers.

**Where it can be used.** Only by its card's owner, only while the card is in the Active Zone, only inside an open window whose declaration has **`abilities: true`** (`windows: [{ id, opened_by, actions, abilities? }]`, a bool defaulting to false; `WindowDraft::abilities`, `Window::abilities()`). Never in the Action phase this phase. A window with `abilities: true` in a ruleset without `effects.active_zone` is a load error, `AbilitiesWithoutActiveZone` at `windows[<id>].abilities`, checked after the Active Zone, because the flag could never do anything; and one whose Active Zone is not `public` is `AbilitiesActiveZoneNotPublic { zone }` at the same path (see Public).

**The Action.** `Action::Activate { player, card, ability }`, the fourth engine variant beside `Declared`, `Answer` and `Pass`: a Declared Action names a ruleset action id and an ability has none. It is recorded, replayed and observed. The checks run in this order: `GameOver`, `UnknownPlayer`, `NotDecidingPlayer`; then `ActivateWhileDecisionPending`, `ActivateWithoutWindow` (the Stack is empty, the Action phase included), `AbilitiesNotInWindow { window }`, `UnknownCard { param: self, card }`, `NotAnActivatedAbility { card, ability }` (out of range, or an effect that is not activated), `NotCardOwner { param: self, card, owner }`, `CardNotInZone { param: self, card, zone: <Active Zone> }`, then each cost in order (`CardAlreadyTapped`, `NotEnoughUntappedCards`, and the others of ADR-0015 and ADR-0037). A rejection changes nothing and has no Events. Listed Activates are `consider`ed through `transition` like every candidate, so the listing is exactly what is accepted.

**Always pushed.** Using an ability pays its cost at once with `self` bound to the card (its Events wake triggers as today), then `ItemPushed` pushes an item whose source is `StackSource::Ability { card, ability }` and whose one Bound Card is `self`, in the zone the card is in **once the cost was paid** (the rule of ADR-0037 for declared actions), then the Trigger Resolution scans the cost's Events and the push, then the win conditions. The trace is the cost Events, `ItemPushed`, the woken triggers. A Pass resolves it: `ItemResolved`, then the `do` of `effects()[ability]` with `self` bound, then the triggers. It Fizzles like any item when `self` has left, `self` included: its cost is not refunded, and `ItemFizzled` is alone. `open_window` reads only an `Action` source at the bottom of the Stack; an `Ability` there, which cannot happen, gives no window and never panics.

**The Legal Actions** of the Player with Priority in a window with `abilities: true` are `Pass`, the window's actions, then each `Activate` of a card of that Player in the Active Zone, in ascending Card Instance Id, then ability index.

**Observing.** `ObservedStackItem::source` is an `ObservedStackSource`: `Action(ActionId)` or `Ability { card: Option<ObservedCard>, ability }`. The card is the Observed Card while the `self` Bound Card has not `left` and **`None` once it has**, which mirrors Observed Bound Card: a handle names a card only while the Viewer sees it, so the source never shows a card that moved to a zone the Viewer cannot see. The observed fold sets it to `None` on any observed move of the card and refuses (`EventDoesNotFit`) a pushed item whose source card is `None`, unseen or not among its bound cards. `ObservedAction::Activate { player, card: ObservedCard, ability }` is listed after the Pass and the Declared Actions of the Player with Priority and translated back like a Declared Action's card (`ActionOfAnotherPlayer`, `UnknownObservedCard`); `TakenAction::Activate { player, card: ObservedCard, ability }` carries a plain Observed Card, because the card was in the Active Zone, which the load checks of an ability's `self` guarantee (see Public). The self-play Relabelling renames the card of an `Ability` source and of an `Activate` through the same permutation as the bound cards.

**The Response Ruleset.** `attack_response` has `abilities: true`. One new catalog card, `skittish_hare` (creature, `cost: 1`, `power: 1`, `fast: false`), carries `activated: { cost: [ { tap: { zone: mana_zone, count: { ref: self.cost } } } ], do: [ { move: { card: { ref: self }, to: hand } } ] }`: it pays 1 mana and returns itself to the hand. **It pays mana and does not tap itself because the target of an attack must be tapped**: a hare whose cost is `tap: self` could never be activated while it is the target, and so could never make the attack Fizzle by moving away, which is the use of the card; paying mana makes it usable on a tapped hare. Two hares are in each sample deck, replacing two of the four `stone_golem`s. The `do` can name only `self`, so the ticket's example "a target creature taps" cannot be written; the bounce is what `self` allows.

**Public.** The Stack is public, so a Bound Card must be seen by every Viewer in the zone it is bound in, or the Observed Stack Item cannot be built (`ObserverOutOfStep`). ADR-0037 guards this for a pushed action with `PushedCardNotPublic`; the same rule applies to the `self` of an ability, in two load checks. (a) In the catalog, the zone `self` is in once the cost was paid, which is the `to` of the **last** `move: { card: { ref: self }, to }` cost step, must be `public`: otherwise `InvalidCardEffect { PushedCardNotPublic { param: self, zone } }` at `cards[<id>].effects[<i>].activated.cost[<k>].move.to`, `k` the position of that step. A cost that moves `self` to a public zone and on is fine as long as the last move ends public. (b) Without a `move` of `self` the zone is the Active Zone, so a window with `abilities: true` needs a `public` Active Zone: `AbilitiesActiveZoneNotPublic { zone }` at `windows[<id>].abilities`, checked after `AbilitiesWithoutActiveZone`. The Response Ruleset's Active Zone is `field`, public.

**Out of scope**, for later tickets: abilities in the Action phase or used from another zone, Choices in an activated `do`, costs beyond the action cost steps (there is no `tap: self` shorthand, `tap: { card: { ref: self } }` is the step), mana abilities or any ability that skips the Stack, coverage counts, the Response Golden Game and pins ([36]) *(Amended by ADR-0039: built in [36])*.

**Conflicts, amended in place.** ADR-0037 (the Stack is public; `PushedCardNotPublic` named only a pushed action's params, its error doc and message now also cover `self`), ADR-0018 (Listing Order), ADR-0019 (the Actions a record holds), ADR-0022 (the envelope's shapes and the order of its checks), ADR-0023 (when triggers are scanned), ADR-0028 to ADR-0030 (the Observed Stack Item, the Taken Action, the Observed Action), ADR-0031 (the Relabelling), ADR-0033 and ADR-0034 (the `Action` variants, where a Choice may stand) and ADR-0037 (`StackSource`, the window declaration, the Legal Actions, the Observed Stack Item source, the Response Ruleset's cards, what is out of scope) each carry an `Amended by ADR-0038` line and mark the affected clause where it stands. ADR-0024 and ADR-0025 do not name the shapes and need no change.

**Status**: accepted
