# Integer arithmetic, strict comparisons, positions and combat

Ticket [41] (#98) of the Phase G roadmap #94 (checkpoint #88 decisions) widens the expression language by four operators and gives the Duel Ruleset the rules they unlock: monster positions and combat between monsters.

**The operators.** `add: [a, b]` and `sub: [a, b]` are int Expressions over two int Expressions, and `gt: [a, b]` and `lt: [a, b]` are bool Expressions over two ints, joining `eq`, `gte` and `lte` (same operand rules: exactly two operands, a list of any other length is a syntax error). The operands of `add` and `sub` are any int Expression: an int literal, a card field or card state ref, a Player ref, a `count`, or another `add` or `sub`. They stand wherever an Expression does (a `where`, an `if`, a `while`, an `amount`), and `eq`, `gt`, `gte`, `lt` and `lte` take them as operands. Evaluation is checked (`checked_add`, `checked_sub`): an overflow is the Rejection `ArithmeticOverflow` (the existing variant, whose meaning is widened from "a `sub` amount" to "an `add` or `sub`"), raised wherever the Expression is evaluated, with the input GameState untouched and no Events, as any Rejection. A non-int operand is the existing `ExpressionTypeMismatch { expected: Int, found }` at the operand (`…where.gte[0].add[1]`, `…add_state.amount.sub[0]`), reported by the same rule as `gte` and `lte` (all operands checked first, then the first one that is not an int). **Still excluded: `or`, `not` and multiplication** (ADR-0016's exclusions, restated): no rule needs them yet. In a win condition the four operators are allowed over Player state or a Subject's refs, and `count` and `first_turn` stay forbidden at any depth: `OperatorNotInWinCondition` is raised at the operator's own path wherever it nests (`win_conditions[x].when.gt[0].add[0]`).

**The Amount is an Expression.** The `amount` of an `add_state` of an action, a cost or a Card Effect stops being a mini-language of its own (literal, ref or `sub` of two): it is an Expression that must type to int, parsed by the same loader code as every other Expression. `AmountDraft`, `AmountOperand` and the loader's amount DTO are removed; `Amount` is a wrapper of the validated int Expression. Consequences, all deliberate: a non-int amount (a ref to a bool or a text, a comparison, a bool or a text literal) is `ExpressionTypeMismatch { expected: Int, found }` at `…add_state.amount`, no longer `ReferenceTypeMismatch`, `InvalidAmount` or a syntax error; a non-int operand of `add` or `sub` is `ExpressionTypeMismatch` at `…add[i]` or `…sub[i]`; a nested operator in an amount is legal; `count` is legal in an amount (ADR-0042 said it was not). A card ref without a name, an undeclared name and the Player-ref errors are unchanged, since they are the Expression's own errors. `InvalidAmount` survives for a **setup or an automatic step**, where nothing binds a card or names a Player to read: the amount stays an int literal there and any other well-formed Expression (an operator, a ref, a bool or a text literal) is `InvalidAmount` at `…add_state.amount`; the model there stays an `i64`. An operator the language lacks (`mul`, `or`, `not`) is now a syntax error (an unknown operator, as in any Expression) in any amount, and no longer `InvalidAmount`; so is a wrong operand count, here as elsewhere. The evaluation reads a card field with its active Field Modifiers, an instance state and a Player's state as they stand, as an amount did. Nothing observable changes in the Small, Effects and Response Rulesets: every amount they write is a literal or a read the Expression language already types the same way, and their digests, pins and Golden Snapshots are untouched.

**ADR-0032's arm.** An alternative whose `where` raises `ArithmeticOverflow` does not fit when the param has several alternatives, as one that raises `DerivedValueOverflow` does: binding tries the next, and with none left the Rejection is `NoAlternativeMatched`; with one alternative the overflow is the Rejection, and listing leaves the card out in both cases.

**Positions and the Duel Ruleset v2** (`meta.version: 3`, the catalog's `ruleset_version` too). A monster's `instance_state` gains `position` (text, init `"attack"`, values `"attack"` and `"defence"`) and `position_fixed` (bool, false: true once the monster arrived or changed position this Turn). Position is face-up and public this phase; face-down cards are Phase H's. Main lists `normal_summon`, `set_monster`, `change_position`, `to_battle`, `end_turn` *(Amended by ADR-0044: v3 Main also lists `tribute_summon_one`, `tribute_summon_two`, `tribute_set_one`, `tribute_set_two` and `play_spell`)*; Battle lists `attack`, `direct_attack`, `end_turn`. `normal_summon` also sets `position` to `"attack"` and `position_fixed` true. `set_monster` has the summon's `where` (so it shares the `normal_summoned` flag and the Monster Zone's room), and sets `normal_summoned`, `position` to `"defence"` and `position_fixed` true. `change_position` takes a monster of the acting Player's Monster Zone whose `position_fixed` is false, sets it true and moves the monster to the other position. The End phase also resets `position_fixed` for the Active Player's monsters (`zone: monster_zone`), so a monster may not change position on the Turn it arrived and at most once a Turn. `attack` takes an `attacker` (the acting Player's Monster Zone, not attacked this Turn, in attack position, not on the Game's first Turn, a clause that states the rule since no opponent monster can exist then) and a `target` (`owner: opponent`, Monster Zone). It sets `attacked` and then, with nested `if`/`else` over `eq`, `gt` and `lt` and damage before destruction in each branch (nested, not a flat list of sibling `if`s: siblings would test again after an earlier branch had moved a card, so the cases would stop being exclusive once derived values can change, while a nested branch tests once): against an attack-position target, the controller of the lower-ATK monster loses the difference (an `add_state` whose amount is `sub: [lower atk, higher atk]`, negative) and that monster goes to its owner's Graveyard; equal ATK sends the target and then the attacker to the Graveyard, with no damage. Against a defence-position target, ATK above DEF sends the target to the Graveyard (no damage), ATK below DEF costs the attacker's controller the difference, equal changes nothing. The restriction to attack position is in the `where` (so a defence-position monster's attack is a Rejection `WhereConditionNotMet` and not a Legal Action), as is `direct_attack`'s, which gains the same clause. Over Seeds 0..100 the Duel self-play ends 95 Games on `life_out` and 5 on `deck_out` (no drawn Game, the longest 225 Actions) *(Superseded by ADR-0044: with the v3 decks, 87 and 13, the longest 218 Actions)*, every Invariant, the Observed Game round-trip and the Relabelling holding; no new Event, so the Observations and the Relabelling needed no change. The Duel pin, coverage counts, Golden Game and timings stay ticket [43]'s.

**Why not the alternatives.** A separate `Amount` operand language with `add` added would have kept two grammars for one idea and a second set of load errors. A bool `defence` state would have worked without text state, but the engine already holds text instance state, `eq` against a text literal and a text `set_state`, so no engine change was needed and the state reads as the rule does. Putting the defence-position check in the effects would have made an illegal attack a spent no-op instead of a Rejection.

**Conflicts, amended in place.** ADR-0016 (the operators, and "arithmetic ... not part of it"; `not`, `or` and multiplication stay excluded), ADR-0015 (the `amount`), ADR-0041 (*Amounts*: "for amounts only", the operand restriction, the load errors, the overflow; the Duel Ruleset v0 text), ADR-0042 (`count` is an Amount; `lte` until `lt`; the Duel v1 direct-attack rule and the self-play results) and ADR-0032 (the overflow arm), each carrying an `Amended by ADR-0043` marker where it stands. ADR-0004 mentions no arithmetic and needs no change.

**Status**: accepted
