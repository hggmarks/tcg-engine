# Resolving triggered Card Effects

Triggered Card Effects now run (ticket [17], #50). This lifts ADR-0022's rejection for the triggered kind only: `UnsupportedTriggeredCardEffect` is deleted, as `UnsupportedEffect` was before it, because nothing can return it any more, and `CardDefinition::effects()` holds the triggered effects in file order. `UnsupportedContinuousCardEffect` stays until ticket [18]; every other check of the envelope is unchanged.

**Matching.** `enter: <zone>` is woken by an `Event::CardMoved` whose `card` is the carrying card and whose `to` is that zone. It does not match `CardCreated`: placing the cards of the decks and creating cards fire nothing, so neither does Game creation (`create_game` never resolves triggers; resolution runs only in `Ruleset::transition`). This resolves the question from the review of ADR-0022's PR: setup placement must never fire a trigger. `turn_start: {}` is woken by `Event::TurnBegan` of the carrying card's owner. Card Effects act only on cards in the **Active Zone**, declared in the ruleset file as the optional top-level block `effects: { active_zone: <zone> }` (the zone must be declared, `DanglingReference` at `effects.active_zone`; `deny_unknown_fields`; `RulesetDefinition::effects_active_zone()`). **With no `effects` block there is no Active Zone and no trigger is ever eligible**, `enter` included (lenient: there is no new required key, only inert Card Effects). **With the block**, `turn_start` fires only if its card is in the Active Zone when the Event is scanned, while `enter: <zone>` fires on arrival in the matcher's own zone, whichever zone that is and whether or not it is the Active Zone (the enter exception), so `enter: trash` fires on arrival in the trash. The Effects Ruleset declares `active_zone: field`.

**Resolution.** After the action's costs and effects, and before the win check, `declarative::triggers::resolve` scans the transition's Events in order from the first, cost Events included, keeping a cursor so no Event is scanned twice. An Event that wakes triggers enqueues them first in first out; the front fires: its `if` is evaluated with `self` bound to the carrying card on the state as it is at that moment (false: no Events), then its `do` runs to completion *(Amended by ADR-0033: until its end or a Choice, which pauses the Resolution)*, and the Events it appended are scanned after the triggers already queued. Resolution ends when every Event is scanned and the queue is empty. **Where trigger Events land:** after all the Events of the transition's own automation, so a `turn_start` trigger's Events follow `PhaseBegan { main }` as the last Events of the `pass_turn` trace; the Start phase's `untap` and `recently_played` reset run before the trigger and cannot undo what it does (a `turn_start` that taps `self` keeps it tapped for the Turn). This is the designed resolution point, not an accident of the call site. **Eligibility is decided at enqueue (scan) time**: a trigger once enqueued fires even if its card has moved since; only its `if` is read at fire time. One Event waking several triggers enqueues them in the canonical order: cards of the Active Player first, then the other Players in seat order, then `state.cards()` order, then the order of the card's `effects`. With the two matchers there are, one Event only wakes the cards of one Player (the mover's, or the Turn owner's), so the cross-Player part of the rule cannot be observed yet; it is implemented so that a later matcher does not change the order. The win conditions still run once, after all triggers, on the final GameState and the whole Event Trace (ADR-0014), so a trigger can cause a `deck_out` loss and `GameEnded` stays the last Event.

**The Trigger Cap is 100.** One transition resolves at most 100 triggers. *(Amended by ADR-0033: one Resolution does, and a Resolution spans the pauses a Choice makes: the cap counts across Answers and is not reset by one.)* Every trigger taken from the queue counts, one whose `if` is false included. The 101st returns `Rejection::TriggerCapExceeded { cap: 100 }`: a typed rejection of the whole transition, never a panic, and the input GameState is untouched because `transition` takes it by reference (ADR-0002). Any other rejection raised inside a fired `do` (such as `StateOverflow`) refuses the whole Action in the same way. By ADR-0018 a Legal Action is one that `transition` accepts, so a capped Action is never listed as legal: self-play (ticket [20]) does not execute it and observe the rejection, and a live Game whose every Action is capped has no Legal Action, which is ADR-0020's `NoLegalAction`. The shipped catalog cannot reach that state. *Superseded by ADR-0026: self-play does observe the rejection, through `listing_with_rejections`, and counts it; and the `NoLegalAction` reading is unreachable in the Effects Ruleset, because `pass_turn` is always listed and resolves no trigger.* 100 is a round number well above what the cards of the Effects Ruleset need and cheap to reach by a loop; a later ADR may change it.

**The `draw` effect.** The named criterion card needs a draw in `do`, so the Action Effect grammar gains `draw: { player, from, to, count }` (`Effect::Draw`, `EffectPlayer::Controller`). It mirrors the Start phase's `draw` step exactly (it shares its implementation): per card, move the Top of `from` onto the Top of `to`; an empty `from` emits `DrawFromEmptyZone` and stops, which reaches ADR-0014's `draw_from_empty` machinery. `from` is an ordered zone (`ZoneNotOrdered`, ADR-0013), `count` an unquoted positive integer (`InvalidCount`, ADR-0009's number rule), both zones declared. `player` is `controller`, the owner of `self`, the only selector of an effect; any other value is `UnknownEffectPlayer`, and `controller` where no `self` is in scope (a ruleset action's effects) is `ControllerOutsideCardEffect`, at the `player` path. No other Action Effect is added.

**Not changed.** A trigger asks for no decision, *(Superseded by ADR-0033 for a Card Effect with a Choice: it pauses the Resolution and the Deciding Player's Answer is an Action of the Game Record, which keeps its shape)* so the Game Record (ADR-0019) and replay are unchanged: a record replays its triggers because they are part of `transition`. `end_turn` stays rejected in a `do` (ADR-0022). The shipped decks are untouched, so the Small and Effects golden games stay equal; five catalog creatures, one per family, are documented in `effects-ruleset.md`. *Amended by ADR-0026: the shipped Effects decks now play the effect cards, so the Effects Golden Game is its own and no longer equals the Small Ruleset's (the equivalence is kept on the Small Ruleset's cards), and the catalog has a sixth triggered creature, `pyre_imp`.* No conflict with an accepted decision: it amends ADR-0022 (the lift above) and extends ADR-0015/ADR-0016's effects with `draw`.

**Amended by ADR-0033:** three clauses above no longer hold as written, and each is marked where it stands: the `do` runs until its end or a Choice, the Trigger Cap is per Resolution rather than per transition, and "a trigger asks for no decision" does not hold for a Card Effect with a Choice.

**Amended by ADR-0026:** three clauses above no longer hold as written, and each is marked where it stands: the shipped Effects decks are no longer untouched (so the golden games no longer stay equal), the catalog has six triggered creatures, and a Game whose every Action is capped (`NoLegalAction`) is unreachable while `pass_turn` is listed, with the Trigger Cap Rejections counted instead.

**Status**: accepted
