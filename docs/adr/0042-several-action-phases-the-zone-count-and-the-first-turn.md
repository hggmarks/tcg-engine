# Several action phases, the zone count and the first Turn

Ticket [40] (#97) of the Phase G roadmap #94 (checkpoint #88 decisions) gives the engine three primitives and the Duel Ruleset the rules they unlock: a Main and a Battle phase, a Monster Zone of at most 3 monsters, a direct attack only on an empty Monster Zone, and no attack on Turn 1.

**Several action phases.** A Turn's phase list may hold **one or more** phases with `actions` (ADR-0012's and ADR-0027's "exactly one" goes). The Game waits in each action phase it enters, for the Active Player (or the Player with Priority, ADR-0037), and each action phase lists its own actions: an action of another action phase is the existing Rejection `ActionNotInCurrentPhase`, the input untouched and no Events, and the Legal Actions are those of the current one. Zero action phases is the load error `NoActionPhase` at `turn.phases` (replacing `InvalidActionPhaseCount`, which is removed: a Turn with none would never wait for a Player). `NoTurnEndingAction` stays per action phase: every action phase lists an action that ends the Turn, so `end_turn` is legal from any of them.

**`advance_phase`.** A new Action Effect `advance_phase: {}` moves to the **next action phase** of the Turn: it enters each phase after the current one in order, running the automatic ones (each emits `PhaseBegan`, then its steps' Events, exactly as `end_turn` runs them), and stops at the first phase with `actions`, ending with `PhaseBegan` of that phase. The Turn, the Turn Number and the Active Player do not change. There is **no new Event**: a phase change is the `PhaseBegan` the engine already emits, so the Observations and the Relabelling need no change. There is no going back to an earlier phase. The target is computed before any Event is emitted. `end_turn` from an earlier action phase **passes over** the later action phases without a `PhaseBegan` (a phase begins when the Game enters it, and the Game waits in an action phase it enters); it still enters every automatic phase after the current one, and the loop that does so is shared with `advance_phase`.

**Where `advance_phase` may stand** is `end_turn`'s place (ADR-0027): only the last top-level effect of an action, so an action has at most one effect that leaves its phase. In an `if` (any depth) it is `AdvancePhaseInIfEffect`; followed by another effect it is `AdvancePhaseNotLast` (in the same document-order walk as `end_turn`, so `[advance_phase, end_turn]` is `AdvancePhaseNotLast` at the first and `[end_turn, advance_phase]` is `EndTurnNotLast`), both at the effect's own path; in a pushed action (one a Response Window lists or opens) it is `AdvancePhaseInPushedAction` at its path, checked where `EndTurnInPushedAction` is; in a Card Effect it is `CatalogErrorKind::AdvancePhaseInCardEffect`, where `EndTurnInCardEffect` stands. An action that advances and is listed by the **last** action phase is `AdvancePhaseFromLastActionPhase { action }` at `turn.phases[<phase>]`, checked in `validate_turn` after the phase loop and `NoActionPhase`, the listed actions in list order; at runtime the same case is the defensive `Rejection::NoLaterActionPhase` (unreachable for a loaded definition, no panic, no Event).

**The `count` expression.** `count: { zone, player }` is an int Expression: the number of cards in that Player's zone, **derived** from the GameState at evaluation and never stored. It stands in any Expression of an action or a Card Effect (a `where`, an `if`, a `while`), wherever an int operand does (`eq`, `gte`, `lte` *(Amended by ADR-0043: and `gt` and `lt`)*); it is not an Amount (arithmetic is [41]'s) *(Amended by ADR-0043: it is an Amount, as every int Expression is, and an operand of `gt`, `lt`, `add` and `sub`)*. `player` is required and takes the selectors of a Player Ref (ADR-0041): `active`, `opponent` (the acting Player's in an action, the controller's in a Card Effect; two Players only) and, in a Card Effect, `controller`. Load errors, in the order zone then player: an unknown zone is `DanglingReference { target: Zone }` at `…count.zone`; a missing `player` is `MissingPlayerSelector` at `…count`; an unknown selector is `UnknownPlayerSelector`, `controller` in an action `ControllerOutsideCardEffect`, `opponent` without 2 Players `OpponentNeedsTwoPlayers`, each at `…count.player`. A count that does not fit an int is the defensive Rejection `CountOverflow { player, zone }`.

**The first Turn in an Expression.** `first_turn: {}` becomes a bool Expression, with the spelling and meaning of the automatic-step Condition `first_turn` (the Turn Number is 1); the Condition is unchanged (ADR-0012), and the two are not unified. "Not on Turn 1" is `eq: [{ first_turn: {} }, false]` (there is no `not` yet). Chosen over the Turn Number as an int ref because the concept and the spelling already exist and it is what the rule needs: an int ref would invite arithmetic on Turn Numbers nobody asked for, and no Player flag stands in for it.

**Win conditions.** A win condition judges the GameState a transition produced for a Player or a card: `count` and `first_turn` in its `when` are `OperatorNotInWinCondition { operator }` (`count` or `first_turn`), at the operator's own path, such as `win_conditions[lost].when.eq[0]`.

**The Duel Ruleset v1** (`meta.version: 2`, the catalog's `ruleset_version` too): Draw, **Main** (`normal_summon`, `to_battle`, `end_turn` *(Amended by ADR-0043 and ADR-0044: v3 Main also lists `set_monster`, the four tribute actions, `play_spell` and `change_position`)*), **Battle** (`direct_attack`, `end_turn`), End. `to_battle` is `advance_phase`. `normal_summon` adds `lte: [count(monster_zone, active), 2]`, so the Monster Zone holds 3 at most (`lte` until [41] adds `lt`) *(Amended by ADR-0043: `lt` exists, and v2 keeps `lte: [count, 2]`)*; `direct_attack` adds `eq: [count(monster_zone, opponent), 0]` and `eq: [first_turn, false]` *(Amended by ADR-0043: v2 also requires the attacker to be in attack position)*. A monster is summoned in Main and attacks in Battle; a Player who never goes to Battle passes over it with `end_turn`. With attacks gated, Duel self-play Games end mostly by deck-out (over Seeds 0..100: 2 `life_out`, 98 `deck_out`, the longest 124 Actions, below the Step Cap; *Superseded by ADR-0043: with combat between monsters, 95 `life_out`, 5 `deck_out`, the longest 225 Actions; superseded again by ADR-0044: 87 `life_out`, 13 `deck_out`, the longest 218 Actions*), as ADR-0041 expected would change once [40] landed. The Duel pin and Golden Game stay ticket [43]'s *(Amended by ADR-0045: [43] did them: the Duel Self-Play Pin and the Duel Golden Game)*.

**Frozen.** The Small, Effects and Response Rulesets, every Golden Game, snapshot and pin are unchanged: none declares a second action phase, `advance_phase`, `count` or the expression.

**Why not the alternatives.** `end_turn` as the only way to leave an action phase would make Battle a separate Turn. A `capacity` key on zones enforced by the engine would put a rule in the generic engine, while `count` in a `where` keeps it in the ruleset, as every other rule is. A new Event for a phase change would duplicate `PhaseBegan`. A Turn Number int ref would invite arithmetic that is not asked for. Emitting `PhaseBegan` for the action phases `end_turn` passes over would claim the Game entered phases it never waited in.

**Conflicts, amended in place.** ADR-0012 (exactly one action phase; `end_turn` runs every phase after the current one; the trace of a Turn), ADR-0027 (exactly one action phase; `InvalidActionPhaseCount` and its position in the validation order; the action phase lists every declared action; `NoTurnEndingAction` per action phase), ADR-0016 (the expression operators), ADR-0018 (the Listing Order is the current action phase's), ADR-0037 and ADR-0038 ("the Action phase": any action phase), ADR-0041 (the expression list is longer; a Turn-1 attack was allowed and the Duel net ended on Life Points), each carrying an `Amended by ADR-0042` marker where it stands. ADR-0028 and ADR-0029 need no change: the phase is already observed and no Event is new; ADR-0022's `EndTurnInCardEffect` is unchanged.

**Status**: accepted

Amended by ADR-0043: `count` is an Amount, `lt` exists, and the Duel Ruleset v2 requires an attack-position attacker for a direct attack and gives different self-play results (marked above).
