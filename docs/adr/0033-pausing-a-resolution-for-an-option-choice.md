# Pausing a Resolution for an Option Choice

A Triggered Card Effect can ask a Player to pick one of several effect lists, and the Resolution **pauses** in the GameState until the Deciding Player answers (ticket [29], #75; checkpoint #67 decisions). This ADR is the pause itself, with the simpler kind of Choice; the Card Choice is a later ticket's, on top of it.

**The Option Choice.** The Action Effect `choose_one: { decider, options: [[effects], ...] }` (`Effect::ChooseOne { decider, options }`, `Decider::{Controller, Opponent}`; `EffectDraft::ChooseOne`). `decider` is `controller` (the owner of `self`) or `opponent` (the other Player). At least 2 options; an option may be empty, so "may" is an Option Choice with an empty option, a pattern and not a keyword; there are no labels. It is allowed only in a Triggered Card Effect's `do`, also nested in an `if` there and inside another option. Anywhere else is a typed load error, found while validating an effect, not by position: in a ruleset action's effects (an `if` of one included) `ChoiceOutsideTriggeredEffect` at `<effect>.choose_one`, detected by there being no `self` in scope; steps and Continuous Card Effects have no effect grammar, so `choose_one` there is the loader's unknown key at its path. `TooFewOptions { found }` is at `choose_one.options` and `UnknownDecider { decider }` at `choose_one.decider`, checked in the order outside-a-Card-Effect, decider, option count, then the effects of each option at `choose_one.options[k][i]`. `end_turn` inside an option is `EndTurnInCardEffect` at its own path, like one in the `do`.

**The pause.** Reaching a Choice ends the transition. The GameState holds `pending: Option<PendingDecision>`, `PendingDecision { decider, kind, paused }` (private fields, accessors), and `PausedResolution { trigger, at, queue, unscanned, resolutions }`: the trigger whose `do` is paused, the `EffectPath` of the Choice (`branches`: `Branch { effect, into }` with `into` one of `Then`, `Else`, `Option(k)`, outermost first, then `choice`, its index in the innermost list), the queued triggers (front first), the Events the paused `do` emitted that no trigger has scanned yet, and the Trigger Cap count so far, the paused trigger included. `DecisionKind` is `Option` and stores no option count: it is read from the catalog through the path, and a path that does not lead to a Choice is `CardDataMismatch`.

**Events.** `DecisionPending { decider, kind, paused }` is the last Event of a pausing transition, before `GameEnded` if that transition ends the Game; `DecisionAnswered { player, answer }` is the first Event of an Answer's trace. `GameState::apply` stores and clears the Pending Decision, so event-sourced consistency holds. While a decision is pending only `DecisionAnswered` and `GameEnded` apply, which makes "DecisionPending is the last Event" structural: `DecisionAlreadyPending`, `NoDecisionPending`, `AnswerFromAnotherPlayer { player, decider }` and `DecisionPending` (any other Event while pending) are the new `ApplyError`s, and `GameEnded` clears the Pending Decision. The observed fold has the same rule (`EventDoesNotFit`).

**Actions.** `Action` is an enum, `Declared { player, action, arguments }` (what the struct was) and `Answer { player, answer }`, with `Answer::Option(index)` and `Action::player()`; the Game Record keeps its shape and holds Answers like any Action. The **Deciding Player** is derived (`GameState::deciding_player()`): the Decider while a decision is pending, otherwise the Active Player. `Rejection::NotActivePlayer` becomes `NotDecidingPlayer { player, deciding }` (the Toy Ruleset's own variant is untouched), and the new rejections are `DeclaredWhileDecisionPending`, `NoDecisionPending`, `OptionOutOfRange { index, options }` and the internal `ChoiceOutsideTriggeredEffect` (a ruleset action's effects paused). The checks run in this order: `GameOver`, `UnknownPlayer`, `NotDecidingPlayer`; a Declared Action then `DeclaredWhileDecisionPending`, `UnknownAction` and the rest as before; an Answer `NoDecisionPending`, `OptionOutOfRange`, then the rejections of running it.

**Listing.** While a decision is pending the Legal Actions are `Answer::Option(0..N)` of the Deciding Player in index order, each through `transition` (a capped one drops out), and `listing_with_rejections` alike.

**Resuming.** The Answer applies `DecisionAnswered`, runs option `k` of the Choice at `paused.at` with `self` bound to `paused.trigger.card`, then the rest of each enclosing list, innermost first, and no `if` on the path is read again (the path says which branch the pause was in). Then the Resolution goes on with the queue, scanning `paused.unscanned` first and then the Events of the Answer's trace after `DecisionAnswered`, counting from `paused.resolutions`. It may pause again, at a path of its own; the new `unscanned` then holds what the old one held followed by what the Answer emitted.

**A pause changes no order.** The Events of a paused `do` are scanned after the `do` completes, together with those after the pause, so trigger order and scan-time eligibility are those of the same choice made with no pause. Scanning at the pause would change them.

**Resolution and the Trigger Cap.** A Resolution runs from the Action that wakes the first trigger until the queue is empty, across pauses. The cap of 100 counts per Resolution, each dequeue once, and an Answer does not reset it: the Answer that would take the 101st trigger is rejected (`TriggerCapExceeded { cap: 100 }`, the input GameState untouched) and is absent from the listing. *Amends ADR-0023.*

**Win timing is unchanged** (ADR-0014): the win conditions run once at the end of every accepted transition, a pausing one included, so `GameEnded` follows `DecisionPending`; a Terminal Outcome clears the Pending Decision and `GameOver` rejects everything after.

**Observing.** Always visible to every Viewer: whether a decision is pending, its Deciding Player and its kind: `ObservedPendingDecision { decider, kind }` in the Observed GameState (`pending_decision()`, `deciding_player()`), `ObservedEvent::DecisionPending { decider, kind }` and `DecisionAnswered { player, answer }` with `ObservedAnswer::Option(index)`. `paused` is never observed. `TakenAction` and `ObservedAction` are enums (`Declared`, `Answer`); Observed Legal Actions list the Deciding Viewer's Answers and `translate_action` turns an Observed Answer back. The self-play Relabelling carries `paused`: its trigger, queue and carried Events go through the same id permutation.

**The `Debug`-line convention.** Making `Action` and `TakenAction` enums changes their derived `Debug` lines, which the frozen Small Ruleset pin and the observed Golden snapshots hash or print. Both stay byte for byte: the test-side renderers (the digest and the observed-snapshot writer, one small helper each) render a Declared Action and a Taken Declared Action as the `Debug` line of the former struct, `Action { player: .., action: .., arguments: [..] }` and `TakenAction { .. }`, and an Answer as its own `Debug`. The engine types have no custom `Debug`. No `.digest` or `tests/golden/` file changes. *Amends ADR-0017.*

**Catalog.** `curious_owl` (creature, cost 1, power 1): on entering the field the controller may draw a card (`choose_one` of `[[draw 1], []]`). It is in the catalog only; the shipped decks do not list it.

**Conflicts, amended in place.** ADR-0023 (the cap per Resolution; "a trigger asks for no decision"; the `do` runs until a Choice), ADR-0017 (the render convention), ADR-0018 (the listing while pending; the Deciding Player), ADR-0028 (the Observed Pending Decision), ADR-0029 (`TakenAction`, the two Observed Events, the fold), ADR-0030 (`ObservedAction`, the listing for the Deciding Player) and ADR-0031 (the Relabelling of `paused`) each carry an `Amended by ADR-0033` line and mark the affected clause where it stands. ADR-0014's win timing and ADR-0019's Game Record are unchanged.

**Status**: accepted
