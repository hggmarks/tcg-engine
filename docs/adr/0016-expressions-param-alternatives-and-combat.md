# Expressions, param alternatives and combat

**Expressions.** One expression language serves the `where` of a param, the `if` of an effect and the `when` of a win condition. An Expression is a literal scalar, a Value Ref, or one operator: `eq: [a, b]`, `gte: [a, b]`, `lte: [a, b]`, `and: [e, ...]` and `is_card_type: [<card ref>, <card type id>]`. Its types are the Field Types. `eq` needs both operands of one type, `gte` and `lte` ints, `and` bools (`and: []` holds), and all give bool; `where`, `if` and `when` need a bool. A Card Ref is not a value (`CardRefNotAValue`). Checking is depth-first and left to right: all the operands of an operator are checked, each with its own errors, before the operator's type rule. Errors are addressed by operator key then operand index (`...where.and[0].eq[1]`). `not`, `or`, arithmetic, card equality and literals in `tap.count` are not part of it.

**Param alternatives.** A param is a list of alternatives `{ zone, card_type, owner?, where? }`: the simple form `{ name, zone, card_type, owner?, where? }` is one, `{ name, one_of: [...] }` is one or more (an empty list is `NoAlternatives`). `card_type` is required in every alternative; `owner` is optional, its only value is `opponent` (any Player other than the actor) and absent means the acting Player *(Amended by ADR-0034: for a Card Choice the acting Player is the controller, the owner of `self`, whoever decides, so `opponent` is the controller's opponent)*. This amends ADR-0015: its param shape, and `owner` also works in the simple form. Binding checks, per param after `UnknownCard`: for one alternative the first failing check in the order owner (`NotCardOwner`, or `NotOpponentCard`), zone of the card's owner (`CardNotInZone`), card type (`WrongCardType`), `where` (`WhereConditionNotMet`); for several, the first alternative that fits wins and none fitting is `NoAlternativeMatched` *(Amended by ADR-0032: an alternative whose `where` overflows a derived read, `DerivedValueOverflow`, does not fit; with one alternative the overflow is the Rejection)*. Validation checks an alternative's keys in the order zone, card type, owner, `where`, and the alternatives in order. The `where` is evaluated on the GameState before the costs, with the bindings made so far and the candidate card. It reads its own param (typed as that alternative's card type alone) and earlier params; a later one is a dangling param.

**Possible card types and narrowing.** A param's possible card types are those of its alternatives, in order, each once. A Value Ref `p.name` must resolve on every one of them, to the same kind (field or state) and type; a type lacking the name is `DanglingReference`, a difference is `InconsistentReference`. The state of `set_state` and `add_state` must be declared with the right type on every possible type. Only an `if` effect whose condition is exactly `is_card_type: [{ref: p}, T]` narrows `p`: to `{T}` in `then` *(Amended by ADR-0032: to the param's own types that are in `[T]`, in the param's order; none is `ImpossibleCardType`, a load error at the test)*, to the other types in `else` (unchanged if none would be left). It does not narrow through `and` or in a `where`. A branch that the test makes unreachable is still checked: `then` against `{T}` *(Amended by ADR-0032: a `then` that no type could reach is a load error, so only `else` can be dead)* and `else` against the unchanged types when removing `T` leaves none, so a dead `else` can fail to load. The `if` of an automatic step keeps its own Condition (`first_turn`) and is not an Expression.

**Effects.** `add_state: { card, state, amount }` adds the integer literal `amount` with `checked_add`; an overflow in either direction is `Rejection::StateOverflow` and a sum equal to the current value emits no Event. `if: <expression>` with `then` and an optional `else` are sibling keys of one effect, like the `if` step; the recursive effect runner also runs `end_turn` inside an `if`. `tap.count` still takes only a ref, although ADR-0015 expected literals here. The known gap of ADR-0012 stayed open and now included an `end_turn` nested in an `if` *(Amended by ADR-0027: closed, `end_turn` is rejected in an `if`)*.

**Expression win conditions.** This amends ADR-0014: `UnsupportedWinCondition` is removed and an expression `when` is supported. The first name of each ref is a card type id, the Subject, and the expression must read exactly one (`InvalidSubjectCount`; an unknown name is `DanglingReference` to a card type). The condition holds for Player P iff some card instance of the Subject type owned by P, in any zone, in `state.cards()` order, makes it true in the GameState the transition produced; `loser: owner` is the owner of that instance. The win check still runs once per transition on the resulting GameState, Players in seat order, the first condition in declaration order being the reason: `leader_dead` comes before `deck_out`.

**Combat.** The Small Ruleset's `attack` is written with these constructs and needs no engine rule: the attacker taps even when nothing else happens, a creature dies at attacker power at least its own and goes to the top of its owner's trash, a Leader loses 1 life likewise. `Event` and `GameState::apply` do not change.

**Status**: accepted

Amended by ADR-0027: the known gap of ADR-0012, which this ADR extended with `end_turn` in an `if`, is closed.

Amended by ADR-0032: narrowing in `then` intersects instead of replacing, and an alternative whose `where` overflows does not fit (marked above).

Amended by ADR-0034: a param is also the spec of a Card Choice, with the controller acting (marked above).
