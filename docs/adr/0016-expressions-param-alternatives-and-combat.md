# Expressions, param alternatives and combat

**Expressions.** One expression language serves the `where` of a param, the `if` of an effect and the `when` of a win condition. An Expression is a literal scalar, a Value Ref, or one operator: `eq: [a, b]`, `gte: [a, b]`, `lte: [a, b]`, `and: [e, ...]` and `is_card_type: [<card ref>, <card type id>]`. Its types are the Field Types. `eq` needs both operands of one type, `gte` and `lte` ints, `and` bools (`and: []` holds), and all give bool; `where`, `if` and `when` need a bool. A Card Ref is not a value (`CardRefNotAValue`). Checking is depth-first and left to right: all the operands of an operator are checked, each with its own errors, before the operator's type rule. Errors are addressed by operator key then operand index (`...where.and[0].eq[1]`). `not`, `or`, arithmetic, card equality and literals in `tap.count` are not part of it.

**Param alternatives.** A param is a list of alternatives `{ zone, card_type, owner?, where? }`: the simple form `{ name, zone, card_type, owner?, where? }` is one, `{ name, one_of: [...] }` is one or more (an empty list is `NoAlternatives`). `card_type` is required in every alternative; `owner` is optional, its only value is `opponent` (any Player other than the actor) and absent means the acting Player. This amends ADR-0015: its param shape, and `owner` also works in the simple form. Binding checks, per param after `UnknownCard`: for one alternative the first failing check in the order owner (`NotCardOwner`, or `NotOpponentCard`), zone of the card's owner (`CardNotInZone`), card type (`WrongCardType`), `where` (`WhereConditionNotMet`); for several, the first alternative that fits wins and none fitting is `NoAlternativeMatched`. The `where` is evaluated on the GameState before the costs, with the bindings made so far and the candidate card. It reads its own param (typed as that alternative's card type alone) and earlier params; a later one is a dangling param.

**Possible card types and narrowing.** A param's possible card types are those of its alternatives, in order, each once. A Value Ref `p.name` must resolve on every one of them, to the same kind (field or state) and type; a type lacking the name is `DanglingReference`, a difference is `InconsistentReference`. The state of `set_state` and `add_state` must be declared with the right type on every possible type. Only an `if` effect whose condition is exactly `is_card_type: [{ref: p}, T]` narrows `p`: to `{T}` in `then`, to the other types in `else` (unchanged if none would be left). It does not narrow through `and` or in a `where`.

**Effects.** `add_state: { card, state, amount }` adds the integer literal `amount` with `checked_add`; an overflow in either direction is `Rejection::StateOverflow` and a sum equal to the current value emits no Event. `if: <expression>` with `then` and an optional `else` are sibling keys of one effect, like the `if` step; the recursive effect runner also runs `end_turn` inside an `if`. `tap.count` still takes only a ref, although ADR-0015 expected literals here. The known gap of ADR-0012 stays open and now includes an `end_turn` nested in an `if`.

**Expression win conditions.** This amends ADR-0014: `UnsupportedWinCondition` is removed and an expression `when` is supported. The first name of each ref is a card type id, the Subject, and the expression must read exactly one (`InvalidSubjectCount`; an unknown name is `DanglingReference` to a card type). The condition holds for Player P iff some card instance of the Subject type owned by P, in any zone, in `state.cards()` order, makes it true in the GameState the transition produced; `loser: owner` is the owner of that instance. The win check still runs once per transition on the resulting GameState, Players in seat order, the first condition in declaration order being the reason: `leader_dead` comes before `deck_out`.

**Combat.** The Small Ruleset's `attack` is written with these constructs and needs no engine rule: the attacker taps even when nothing else happens, a creature dies at attacker power at least its own and goes to the top of its owner's trash, a Leader loses 1 life likewise. `Event` and `GameState::apply` do not change.

Status: accepted
